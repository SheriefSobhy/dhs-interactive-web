Flooth · Privacy

Privacy Policy

Last updated: October 15, 2026

This policy explains how Flooth Local V1 handles information when you use the app.

What Flooth stores on your device

Flooth Local V1 stores the information you enter to manage your finances, including profile details, wallet names and currencies, balances, categories and their colors, budgets, income and expense records, descriptions and dates, transfers, and recurring schedules. These records are held in Flooth’s app-private SQLite database. Local Mode does not send those financial records to a Flooth cloud service, and core financial tracking works offline.

Flooth also saves app preferences on the device, including your appearance, reminder settings, and Usage Analytics choice. Android’s configured backup rules exclude Flooth’s SQLite financial database from cloud backup. Device-to-device transfer is not disabled, and preferences are not excluded by those database rules; transfer behavior may depend on Android, the device manufacturer, and your device settings.

Encrypted backups

You can request an encrypted backup and choose where Android’s document picker saves it. Flooth encrypts the backup file using a passphrase you provide before saving it. The file may contain your financial records. Flooth does not upload that file to a Flooth server in Local Mode. The storage or file-provider service you choose may store or synchronize the encrypted file under its own terms. Keep the passphrase separately: Flooth cannot recover it. Restore replaces the current Local Mode financial data only after you review and confirm the operation.

Optional Firebase Analytics

Flooth provides a Usage Analytics control in More → Privacy. You may turn it on or off there. When enabled and operating as intended, Firebase Analytics can receive app-usage and engagement information. Flooth may also send a parameter-free event after each successful action in these groups: creating an income or expense transaction, creating a wallet transfer, creating a recurring transaction schedule, or successfully exporting an encrypted backup. These custom events do not include parameters such as financial amounts or balances, descriptions, wallet or category names, transaction identifiers, email addresses, backup filenames, or backup passwords.

Firebase Analytics may process technical and usage information, app/device or installation identifiers, and approximate geographic information inferred from network information. Flooth does not describe this telemetry as anonymous. Flooth configures Analytics collection to default off and applies the saved choice in Flutter after reading it at startup. Android initializes Firebase before Flutter starts, however, and we have not verified every upgrade case where Firebase may retain an earlier enabled collection setting while Flooth’s preference is missing, invalid, or unreadable. We therefore cannot promise that collection is blocked before Flutter reconciles consent in every such case. This limitation is being investigated; it is not a claim that the startup edge case is resolved.

Turning Usage Analytics off tells Flooth to disable future Analytics collection when the app applies that choice. It does not delete data already collected by Firebase. Firebase service settings and retention controls can affect how long previously collected Analytics data is retained; Flooth’s current Firebase Console retention settings have not been verified for this policy draft.

Firebase Crashlytics

Release builds use Firebase Crashlytics independently of the Usage Analytics choice. Turning Usage Analytics off does not turn Crashlytics off. When a crash or reportable error occurs, Crashlytics may send diagnostic information to Firebase, such as stack traces, relevant app state, device metadata, and Firebase-related identifiers. Flooth does not intentionally attach financial records to custom Analytics events or crash reports, but diagnostic state and Analytics breadcrumbs may overlap when breadcrumbs are available. Do not assume that disabling Analytics prevents crash diagnostics from being transmitted.

Firebase documents Crashlytics collection of a Crashlytics installation UUID and a dependency on Firebase Installations, which uses a Firebase Installation ID. Analytics can use an app-instance identifier. Flooth also configures Google Analytics Advertising ID collection and ad-personalization signals off and does not include ads in this release. These settings do not mean that Firebase uses no identifiers.

Firebase currently states that Crashlytics retains crash stack traces, extracted minidump data, and associated identifiers such as Crashlytics Installation UUIDs and Firebase Installation IDs for 90 days before starting removal from live and backup systems. Flooth has not verified project-specific settings that may affect this service. Analytics retention depends on the Firebase property settings, which have not been verified for this release. Turning off Usage Analytics does not delete Crashlytics reports or change Crashlytics collection. See Firebase’s retention information.

Network use and other providers

Local financial features do not need an account or Flooth API connection. Firebase services may use the Internet to deliver release crash diagnostics and, after Analytics is enabled, usage telemetry. Android’s document provider handles the location you choose for an exported backup. Notifications and reminders are scheduled on the device; notification permission is requested where Android requires it.

Retention and deletion choices

Your Local Mode financial records remain in the app database until you delete them through available app features or remove/reset Flooth’s app data or uninstall Flooth. Clearing app data or uninstalling can permanently remove the on-device database. Keep an encrypted backup somewhere separate if you need a recovery copy. Delete exported backup copies through the provider where you saved them.

Turning Analytics off stops future collection after Flooth applies the setting; it does not erase earlier Analytics data. Flooth does not provide an in-app account deletion flow in this Local V1 release because it does not create a Flooth account. Firebase diagnostic and Analytics data are subject to Google’s/Firebase’s service retention and deletion controls, which Flooth does not represent as an immediate deletion on opt-out.

Security

The SQLite database is stored in app-private storage; this statement does not mean that the database file itself is encrypted. Exported Backup V2 files are encrypted before they are written to the selected destination. Firebase states that its Android SDK data listed for Play disclosures is encrypted in transit using HTTPS. No storage or transmission method can be guaranteed completely secure.

Children, changes, and contact

Flooth is a general personal-finance utility and is not designed for children. This policy may be updated when the app or its data practices change. For privacy questions, contact DHS Interactive at dhs.interactive@gmail.com. For data removal options, see Flooth data deletion information.
